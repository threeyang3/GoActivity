# 飞书 Bitable 视图设计清单

> 当前文档对应 GoActivity 通过 `POST /setup/feishu-views` 自动维护的 11 个主视图。
> 2026-07-12 已在真实飞书 Base 中逐个校验，当前布局与线上状态一致。

## 设计原则

- 面向观众的视图：优先把时间、地点、报名、票价、嘉宾等决策信息放到前排。
- 面向管理的视图：优先展示状态、置信度、关联原因、来源、更新时间。
- 少而精：避免把大量空白列放在前排，专题视图只保留本场景真正有用的字段。
- 幂等维护：视图由 `POST /setup/feishu-views` 更新；若飞书端已有脏视图，会按需要重建。

## 主视图总览

| # | 视图名称 | 类型 | 用途 |
|---|---|---|---|
| 1 | 全部活动 | Grid | 默认总表，查看全部未归档且未过期的有效活动 |
| 2 | 今日执行 | Grid | 今日/近期需要处理或准备参与的 upcoming 活动 |
| 3 | 演出与放映 | Grid | 面向观众决策的专题视图，突出时间/地点/票价/演出信息 |
| 4 | 讲座论坛 | Grid | 面向内容判断的专题视图，突出嘉宾/头衔/主题/系列 |
| 5 | 比赛征集 | Grid | 面向报名决策的专题视图，突出比赛信息/截止时间/奖项/报名链接 |
| 6 | 招募报名 | Grid | 面向报名执行的专题视图，突出报名方式/截止/人数限制 |
| 7 | 用户置顶 | Grid | 用户标记的重要活动，便于集中回看 |
| 8 | 待人工处理 | Grid | 仅保留失败记录，供人工排查抽取/同步问题 |
| 9 | 来源巡检 | Grid | 按公众号巡检数据质量和来源活跃度 |
|10 | 过期回看 | Grid | 查看已结束但未归档的历史活动 |
|11 | 活动归档 | Grid | 仅保留归档后的基础信息，用于追溯 |

## 各视图配置

### 1. 全部活动

- 过滤：
  - `保留决策 != keep_recap_lowest`
  - `保留决策 != drop_past_event`
  - `时间状态 != expired`
  - `状态 != ignored_non_event`
  - `状态 != archived`
- 排序：`开始时间 ↑`
- 显示字段：
  - 标题、活动类型、开始时间、结束时间、活动地点、主办方、嘉宾、报名方式、报名截止、票价信息、状态、时间状态、海报附件、公众号、原文链接、摘要

## 维护与排障

### 自动维护

```bash
curl -X POST http://localhost:8000/setup/feishu-views
```

- 该接口会按当前代码中的 `VIEW_CONFIGS` 幂等更新视图。
- 若飞书侧已有“脏视图”，服务会校验 `visible_fields`，必要时先创建并验证替代视图，验证成功后才删除旧视图。

### 已验证的特殊情况

- 2026-07-12 曾出现旧的 `演出与放映` 视图对象不响应 `visible_fields` 更新的问题。
- 同一套字段配置在新建验证视图中可正常生效，说明是旧视图对象状态异常，而不是字段方案错误。
- 2026-07-13 起采用安全替换：先创建同名替代视图并完成配置验证，再删除旧视图；若创建或验证失败，旧视图保持可用。

### 常见问题

- `待人工处理` 视图创建失败：
  - 先检查飞书状态字段是否真的存在 `failed_sync`、`failed_extract`。
- 视图看起来“更新成功”但列顺序没变：
  - 先重新调用 `POST /setup/feishu-views`。
  - 若仍异常，优先怀疑飞书旧视图对象状态污染，而不是字段名拼写错误。
- 日历/看板/其他历史视图仍存在：
  - 它们可能是人工创建或旧版本遗留视图，不属于当前 11 个主视图的自动维护范围。
